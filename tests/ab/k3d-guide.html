k3d Field Guide

1The picture

Four boxes, one inside the other. Every problem lives in exactly one of them.

Windows 11Your files, your terminal, kubectl, k3d, docker
Docker DesktopA small Linux machine (WSL2) that runs containers. 16 CPUs, 55 GB.
egap-registryA shelf for images. Port 5050.
k3d-egap-server-0One container that is the whole k3s cluster.
PodsYour EGAP runs. Made by Jobs.

k3s is a small Kubernetes. It does not run on Windows directly. k3d is a tool that starts k3s inside a Docker container, which is why Docker Desktop must be running first.

2The words

WordMeaningHere

ContainerA running copy of an image.

ClusterThe boss (k3s) plus the machines it controls.egap, one node

ManifestA YAML file that describes what you want.tests/ab/ab-test.yaml
Kubernetes works by desired state. You do not tell it "start this now". You hand it a file saying "this Job should exist". It works out the steps.

4The daily loop

Run every command from the EGAP repo folder.

  1. Check the cluster is up. You want one node, status Ready. 
    kubectl get nodes
  2. Put the image on the shelf. 
    docker push localhost:5050/egap:old
    See what is on the shelf: 
    curl http://localhost:5050/v2/_catalog
  3. Hand over the order. Add -l variant=old to start only one side. 
    kubectl apply -f tests/ab/ab-test.yaml
  4. Watch. -w keeps the list live. Ctrl+C stops watching, not the run. 
    kubectl get pods -l app=egap-ab -w
  5. Read the output. 
    kubectl logs -f -l variant=old
  6. Collect results. They are already on Windows in egap-ab\out\. Compression numbers: 
    kubectl logs -l app=egap-ab --tail=-1 --prefix | findstr COMPRESS_SUMMARY
  7. Clear before the next run. A Job cannot be edited, only replaced. 
    kubectl delete -f tests/ab/ab-test.yaml
    This removes Jobs, pods and their logs. It does not touch output files.

5On, off, rebuild

Pause and resume

Stop frees CPU and RAM. Nothing is lost.

k3d cluster stop egap
k3d cluster start egap

After a reboot

Start Docker Desktop and wait for it. Then check with kubectl get nodes. If the node is missing or NotReady, run k3d cluster start egap.

Rebuild from nothing

Needed when you change what folders are mounted. Takes about 15 seconds.

k3d cluster delete egap
k3d cluster create egap --no-lb --registry-create egap-registry:0.0.0.0:5050 --volume "C:\Users\theda\egap-ab:/data@server:0" --k3s-arg "--disable=traefik@server:0" --k3s-arg "--disable=servicelb@server:0"

Then push your images again.

What each flag does
FlagWhy
--no-lbNo load balancer. Batch jobs serve no web traffic.
--registry-createMakes the image shelf and tells the cluster to trust it.
--volume A:B@server:0Windows folder A appears as B inside the node.
--disable=traefik, servicelbTurns off web-routing parts you do not use.

To add the Kraken2 database, add a second volume: --volume "C:\path\to\kraken2_db:/kraken2_db@server:0", then mount it in the job file.

Docker Desktop error dialog. Click Quit. Never click "Reset to factory defaults": it can delete every image and volume. On 2026-09-29 Docker failed to start because of stale socket files in %LOCALAPPDATA%\Docker\run and %LOCALAPPDATA%\docker-secrets-engine. The fix was to quit Docker, rename those two folders, and start Docker again. Quit Docker from the tray before shutting down to avoid it.

7Status and fixes

Two commands answer almost every question.

kubectl describe pod -l app=egap-ab

Read the Events list at the bottom. It says what the cluster tried and what went wrong.

kubectl logs -l variant=old --tail=50

This is what the program itself printed.

StatusMeaningFix
PendingNot enough free CPU or RAM for what the pod asked.Wait for another pod to end, or lower requests.
ContainerCreatingPulling the image. Big images take minutes.Wait.
ImagePullBackOffImage not found.Push it. Check the name uses egap-registry:5050.
RunningWorking.
OOMKilledUsed more memory than its limit.Raise limits.memory, or lower --ram_gb.
ErrorThe program exited with a failure.Read the logs.
CompletedFinished without error.

Wrong cluster?

kubectl config current-context

Should print k3d-egap. If not:

kubectl config use-context k3d-egap

Known trap on this machine

k3d image import fails with content digest ... not found. Use docker push to the registry instead.

8How the job file works

One Job, shortened. The second Job is the same with new and egap:fastb.

kind: Job
metadata:
  name: egap-old
  labels: {app: egap-ab, variant: old}   # tags used by -l filters
spec:
  completionMode: Indexed                # numbered pods: 0, 1, 2
  completions: 3                         # three samples
  parallelism: 1                         # one at a time
  backoffLimitPerIndex: 0                # a failed sample is not retried, others still run
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: egap
          image: egap-registry:5050/egap:old
          command: ["bash", "-c"]
          args: [ ...script... ]         # pick sample by number, run EGAP, run final_compress
          resources:
            requests: {cpu: "7", memory: 24Gi}   # reserved for this pod
            limits:   {cpu: "7", memory: 24Gi}   # hard ceiling
          volumeMounts:
            - {name: data, mountPath: /data/input, subPath: input, readOnly: true}
            - {name: data, mountPath: /data/out,   subPath: out/old}
      volumes:
        - name: data
          hostPath: {path: /data}        # the Windows folder, as seen by the node

Why it is a fair test

Held the sameHow
InputBoth Jobs read the same TSV, mounted read-only.
CPU and memoryrequests equals limits, same numbers in both.
Load on the machineAlways one old pod and one new pod at once.
ScriptIdentical text in both Jobs.
DifferentOnly the image.

Rules of thumb

  • A container still sees all 16 CPUs even with a limit of 7. Always pass the thread count to the tool.
  • For clean timing, run one Job at a time. Parallel runs share the disk.
  • Writing to a Windows folder from Linux is slow. Fine for E. coli. Move data into WSL for big genomes.
  • Do not run docker build . from the EGAP folder. It holds 150 GB and has no .dockerignore. Use the command at the top of Dockerfile.fastb.

9Practice

Five drills. Each takes a few minutes and cannot hurt your data. Do them when no real run is active.

Drill 1: look around

List everything in the cluster, including the parts k3s runs for itself.

kubectl get pods -A

Expect: a few pods in kube-system such as coredns. Those are the cluster's own helpers.

Drill 2: run a tiny Job 
kubectl create job hello --image=egap-registry:5050/smoke:1 -- bash -c "nproc; ls /"
kubectl logs job/hello
kubectl delete job hello

Expect: 16, then a folder list. You made, read and removed a Job.

Drill 3: cause ImagePullBackOff on purpose 
kubectl create job broken --image=egap-registry:5050/does-not-exist:1 -- true
kubectl describe pod -l job-name=broken
kubectl delete job broken

Expect: the Events list says the image could not be pulled. Now you know what that failure looks like.

Drill 4: stop and start the cluster 
k3d cluster stop egap
kubectl get nodes
k3d cluster start egap

Expect: the middle command fails to connect. After start it works again and the shelf still holds your images.

Drill 5: see who uses what 
kubectl top pods
kubectl describe node k3d-egap-server-0

Expect: live CPU and memory per pod, then an "Allocated resources" block showing how much of the node is reserved.
